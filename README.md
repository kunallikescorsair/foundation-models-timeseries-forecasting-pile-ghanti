# Evaluating Foundation Models for Time Series Forecasting on the Time Series PILE

This repository contains the cleaned benchmarking code, notebooks, and final result summaries for a UTS capstone project evaluating time series foundation models on selected datasets from the Time Series PILE.

## Project Overview

Foundation models have shown strong performance in natural language processing and computer vision, but their practical value in time series forecasting is still being actively explored.

This project benchmarks modern time series foundation models against traditional forecasting baselines across multiple domains and forecast horizons.

The project evaluates:

* Forecasting accuracy
* Generalisation across datasets and domains
* Short- and long-horizon performance
* Runtime efficiency
* Peak memory usage
* Model reliability and failed runs

## Models Evaluated

Traditional forecasting models:

* Naive
* Seasonal Naive
* ARIMA
* Prophet
* LSTM

Foundation models:

* TimesFM
* Tiny Time Mixer (TTM)
* Uni2TS

## Selected Datasets

The final benchmark uses nine datasets across finance, energy, and retail.

| Domain  | Datasets                                           |
| ------- | -------------------------------------------------- |
| Finance | `bitcoin`, `fred_md`, `m1_monthly`                 |
| Energy  | `electricity_weekly`, `saugeenday`, `solar_weekly` |
| Retail  | `car_parts`, `nn5_daily`, `nn5_weekly`             |

## Forecasting Setup

Each dataset is evaluated under both short- and long-horizon forecasting settings.

Forecast horizons are selected using dataset metadata where available. When metadata horizons are not available, a fallback capped strategy is used. These fallback values act as upper bounds rather than fixed horizons, and final horizons may be smaller when required by dataset-specific sequence-length constraints.

## Evaluation Metrics

The benchmark uses:

* MAE
* RMSE
* sMAPE

sMAPE is used as the primary comparison metric because it is scale-independent and more comparable across datasets with different units and magnitudes. MAE and RMSE are also retained as supporting metrics to measure absolute forecast error and sensitivity to larger errors.

## Source Code Modules

The reusable project code is stored under `src/`.

* `src/models/`: model wrappers for traditional and foundation forecasting models
* `src/experiments/`: experiment runner and result aggregation utilities

## How to Run

This project was developed using Python 3.11.4.

1. Clone the repository.

```bash
git clone https://github.com/kunallikescorsair/foundation-models-timeseries-forecasting-pile-ghanti.git
cd foundation-models-timeseries-forecasting-pile-ghanti
```

2. Create and activate a virtual environment.

```bash
python -m venv .venv
source .venv/bin/activate
```

3. Install dependencies.

```bash
pip install -r requirements.txt
```

4. Run the setup notebook.

```text
notebooks/00_setup.ipynb
```

5. Run the dataset experiment notebooks.

```text
notebooks/03_electricity_weekly_experiment.ipynb
...
notebooks/13_car_parts_experiment.ipynb
```

6. Run final analysis if raw experiment outputs are available.

```text
notebooks/14_final_analysis.ipynb
```

## Key Findings

The final results showed that TimesFM was the most consistent model overall across the selected dataset-horizon tasks. Simple traditional baselines such as Naive and ARIMA remained competitive on some simpler or repetitive datasets.

Runtime analysis showed that TimesFM provided a stronger balance between accuracy and scalability than slower models such as LSTM.

TTM showed adaptation benefits on selected NN5 retail datasets, but it also produced many failed runs in some settings. This shows that practical deployment suitability depends on reliability as well as accuracy.
